# RULER · Codex 自主开发工作流（可导入仓库）

目标：**用户仅通过中文需求、自动测试结果、安装包与运行画面参与验收**。阶段 0 已补充基础工程，当前状态和运行/下载方法见 [README.md](README.md) 与中文验收报告；完整业务尚未开发完成。保留《RULER-原始需求-v3.md》的技术栈、12 阶段、业务规则。

## 你只做 5 件事
1. 在 GitHub 创建 **Private** 私有仓库 `ruler`，建议勾选 README 或创建空仓库均可。勿上传真实当事人信息和密钥。
2. 解压此包，将**包内的文件和文件夹**放到 GitHub 仓库**根目录**（特别是 `AGENTS.md`、`.github/`、`docs/`）。不要额外套一层 `RULER-Codex-Autonomous-Workflow/`。
3. 在 Codex 将这个 GitHub 仓库连接为工作环境。首条任务复制 `给Codex的第一条任务.md` 的内容。由 Codex 在仓库中直接修改源文件、创建分支并提交 PR；不要让它在聊天中逐文件粘贴代码。
4. 每次让 Codex 提交一个 PR；看 PR 的中文验收说明与 GitHub Actions 的绿色检查。下载 APK/Windows ZIP 实测，按 `docs/用户验收手册.md` 决定“通过/不通过”。
5. 不通过时把实际表现（附非敏感截图）反馈给 Codex；通过时合并 PR，再推进下一个任务。**不要在主分支上直接尝试生产部署**。

## 一个完整循环
中文功能需求 → Codex 读取 `AGENTS.md`/原始需求 → 小步修改代码 → 本地执行相关测试 → GitHub PR → Actions 自动验证/构建 → 中文验收报告 + 下载产物 → 你点选测试 → 通过后合并。

## 何时需要自己作决定？
需求矛盾、费用支出、云服务开户、实名验证、生产数据访问、正式发布、安全边界、第三方平台规则改变时，必须由你确认。Codex 无法替代真正的法律、安全合规审查。

## 关于构建
当前已包含 NestJS/Flutter 基础源码，阶段 0 CI 对真实工程执行检查，工程缺失会失败，不会用跳过代替通过。禁止利用跳过检查、伪造截图或空测试让 CI 变绿。构建产物通过 GitHub 仓库 Actions → 选择成功运行 → Artifacts 下载；Windows 为压缩包，Android 为 APK。实际已运行结果见中文验收报告。APK 测试版并非上架包，签名/发布另需安全处理。
