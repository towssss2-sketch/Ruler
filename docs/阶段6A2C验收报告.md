## 用户可见变化

归集历史的已指派文件增加“归档去向”：显示当前案号、法院、文件分类，提供“打开所属案件”和“撤回待定区”。在线打开该案文件页，离线打开体验案件详情。返回后独立重读材料列表，不把打开前的旧状态留作当前结果。

撤回需要确认。确认后正式案件文件从列表移出，材料回到待定区，原附件仍可下载，用户可以重新选择案件及全部 11 类中的任意分类。原件和历史副本保留，已用空间不减少；重新归档会新增一份副本，既有归档确认页说明容量。撤回不是物理删除，也不是自动改派。

重复撤回幂等；响应丢失后可重试。已经重新归档时，旧撤回操作不会影响新归档；旧的归档请求也不能把刚撤回的材料重新归档。失败保留当前页面，成功后列表加载失败只重新读取，不重复写入。取消没有副作用，等待期间禁止重复点击与返回，会话失效销毁旧账号页面。

文件已有其他未删除版本时阻止撤回，避免移除后来上传的材料；只有未完成的新版本票据时可撤回，该票据后续登记会被既有版本校验拒绝。普通删除文件不能冒充撤回；删除整个案件沿用原有级联软删除归集记录规则，此时不可继续查看或撤回。离线同步提供可点击流程，只操作本次内存示例，没有真实原件。

## 用户如何体验

1. 使用本轮 CI 的 Android APK 或 Windows 测试 ZIP（最终链接见 PR），进入“开始虚构体验”。
2. 新建虚构案件，进入“材料待定区”，添加虚构文件示例，按“服务合同”归档到该案。
3. 在“归集历史”点击“归档去向”，检查案号、法院和分类；点击“打开所属案件”，查看该案示例文件，然后返回。
4. 再打开“归档去向”→“撤回待定区”，先取消一次确认材料未变化，再确认撤回。
5. 待定区应再次出现原文件。选择“法院文件”等新分类重新归档，在去向和案件文件页核对变化。
6. 回复“通过”或“不通过＋现象”。无需阅读代码、改配置或运行终端。

安装包没有公开测试地址或安全账号，真实设备上传/联网体验仍待 D-10；本轮不购买服务器、开放公网、提交生产部署或自动合并。

## 工程约定与风险

- `GET /ingestion/:id/assignment` 对本人未删除材料查询当前归属，并再次限制案件当前 OWNER 与未删除文件；仅返回案号、法院、类别和内部标识，不返回键、正文、当事人或失效案件摘要。
- `POST /ingestion/:id/withdraw` 严格接收 caseId/documentId；统一案件授权后，按案件→用户→归集记录顺序锁定，核验本次文档。软删文档、清空 matchedCaseId、返回 PENDING_MATCH、版本递增及审计在同一事务提交；不访问或删除对象、不修改配额。幂等由本次文档撤回审计与当前状态共同确认，忽略后的重复请求不会恢复材料。
- 新增向前迁移 `20261025000000_ingestion_assignment_revision`，IngestionRecord.assignmentRevision 默认 0、非负。归档输入新增 revision，缺省 0 兼容旧客户端首次归档；准备/最终登记均校验当前版本，阻断两次事务之间的撤回竞争。客户端从材料响应读取版本，坏值整次拒绝，不将错误当作初始版本。
- 撤回后再归档生成新的文档，历史软删文档和票据继续保留，不复用旧文档身份。旧客户端没有新版本字段，撤回后的归档会明确失败，需使用本轮客户端。新客户端和旧后端不配套，不能混合发布。
- 已签发下载链接最长十分钟内仍可能有效。暂不撤回普通已删除文件、已删除案件、已有其他保留版本、缺少原附件或非人工 ASSIGNED 状态。本文不承诺释放空间或恢复已删除案件。
- 离线仅模拟元数据，移出示例不保留可下载字节，也不模拟实际容量；归档版本及本次文档身份与线上保持一致。D-05 法律期间、D-06 依赖维护、D-08 协作、D-10 公开环境状态不变；无新依赖、AI 调用、任务建议或真实渠道。

## 回退

保留新增列、原密文、对象、票据和容量；不回滚数据或删列。可回退客户端隐藏入口，旧版仍能查看既有案件文件。后端若回退到不支持本轮状态的版本，先关闭相关写入口或前向修复，不能让旧服务继续处理撤回后的重新归档。未经验收的 PR 栈均不自动合并。
