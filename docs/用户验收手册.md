# 完全不懂编程的验收指南

## 你只需要看三样东西
1. **验收卡片**：PR 说明是否交付了你要的功能，是否列出了失败或未测试内容。
2. **检查结果**：GitHub → Pull requests → 对应 PR → Checks；绿灯表示配置的检查通过，灰色跳过不算通过。也可到 Actions 查看每项。
3. **安装包/运行效果**：GitHub → Actions → 选择成功运行 → 页面底部 Artifacts。`ruler-android-debug-apk` 是 Android 测试包；`ruler-windows-test-zip` 是 Windows 解压包。不同工作流会分别出现，不保证每次 PR 均有两个包。未产生时要求 Codex 说明。

## 每项功能做五项体验判断
- 能否找到功能入口？按钮是否清楚？
- 能否输入虚构测试数据并保存？
- 关闭重开后是否还在？失败时是否有明确提示？
- 是否能看到正确的案件/任务/文件归属？切换账户是否不会看到别人的信息？
- 操作结果是否与你的中文要求一致？

不要使用真实客户资料进行测试。最好使用两个完全虚构测试账号验证不会串案。

## 如何反馈
- **通过**：`通过。功能与预期一致，可以合并这个 PR，继续下一项。`
- **不通过**：`不通过。环境：安卓/Windows；操作路径：……；我期望：……；实际出现：……。请在同一个 PR 修复、运行测试、重交安装包。`
- **不确定**：`暂缓验收。请提供该功能 3 张不含隐私内容的演示截图和逐步点击说明。`

## 用户验收并不意味着什么？
不意味着已经安全合规、能正式上线、法院平台稳定授权、计费没有法律风险。生产前必须有独立复核。
