# 阶段 3 案件管理约定

本阶段基于未合并的阶段 2 分支；用户要求继续开发不等于验收。仅开发/测试环境与虚构资料，不调用法院、真实邮件、AI、支付或生产存储。

## 接口与输入

| 接口 | 行为 |
|---|---|
| POST /cases | 事务创建案件、至少一名当事人、有效 OWNER 成员、审计 |
| GET /cases | 本人主办案件分页；关键词查案号/当事人名/案由；法院/阶段/状态过滤；更新时间与 UUID 稳定排序 |
| GET /cases/:caseId | 活跃当事人、当前版本文件数、未完成任务数；敏感详情在授权后解密 |
| PATCH /cases/:caseId | 部分更新案件；提供 parties 时按完整列表同步，带本案有效 id 保留/修改、不带 id 新增、遗漏的原当事人软删除并吊销预留门户授权 |
| DELETE /cases/:caseId | 事务软删除可变关联记录，保留追加式日志；有法定期间或其他用户归集记录时保护性拒绝 |
| POST /cases/:caseId/conflict-check | pg_trgm similarity ≥ 0.6；查询本人所有历史案件/当事人，含软删除历史，排除当前案件，按案件聚合及分页 |

- 案号中英文括号统一，去空白，支持 `(2026)浙0302民初16812号`；同主办律师、活跃案号及法院重复返回 40901 和本人已有案件 ID，不回显他人资料。
- 金额只能为非负十进制字符串，最多十二位整数、两位小数；响应保持两位小数，不转换成浮点金额。敏感可选字段传 null 清空，省略保留。
- 新接口使用原 v3 已指定的 class-validator DTO；固定 0.14.4，与 NestJS 10 / Swagger 8 兼容。未知字段、原型字段、非法嵌套当事人、无界分页全部拒绝。未新增清单外依赖；阶段 2 已有的 zod 鉴权输入验证保持原行为。
- 默认 page=1/pageSize=20，最大页码 9999、每页 100；冲突检查同样分页。协作组 `group=collaborated` 明确返回空列表及 `collaborationEnabled=false`，不是已完成协作权限。

## 权限、加密及事务

- 单案接口统一使用 CaseAccessGuard，事务内再次查所有者并锁父案件；更新/删除用排他行锁，读详情/冲突检查用共享行锁。不存在与无权访问统一 403。
- 列表只读当前用户；冲突查询是 Prisma 参数化 SQL，阈值不可由请求覆盖，结果只提供候选案件，不能替代律师判断。
- FIELD_ENCRYPTION_KEY 为独立 32 字节环境密钥，经 zod 校验，不得与鉴权密钥相同。已有开发初始化脚本只向忽略的 .env 补充缺失随机密钥，绝不覆盖旧密钥。遗失密钥无法解密已有字段；生产密钥托管和轮换尚未实施。
- AES-256-GCM 分别加密备注、书记员电话、身份证文本、当事人电话和地址；AAD 绑定模型、UUID 和字段。列表不返回这些字段，详情解密失败整次拒绝。
- 所有写操作与审计同事务；冲突查询也追加检查审计。审计只有动作、字段名、数量和内部标识，不保存案情、手机号或请求正文。
- 软删除不物理清除对象存储，不修改尚未实现的容量计费，不删除用户、钱包或共享配置。AuditLog / ClientAccessLog / RTTransaction 追加式历史始终保留。

## 尚待业务确认的删除冲突

原 v3 第 3 节要求级联软删除，第 5 节又禁止删除 DEADLINE_RULE 任务。此处采取保守保护：只要案件含未删除法定期间记录，删除返回 40902，整个案件与任务不改变；可正常标记结案。即使期间任务已完成，也不会通过案件删除绕过限制。没有自行确定法律期限或删掉提醒。

其他用户拥有的归集记录同样不由案件所有者擅自归档，返回 40903；完整协作归属规则留在阶段 9。上述保护测试已实现，D-05/D-08 仍待对应阶段专业及权限决策，不因本 PR 关闭。

## 回退

本阶段没有新增或改写数据库迁移。未合并时保留 PR 或停止使用该分支即可；若将来合并后回退业务提交，保留已加密数据及原字段密钥，禁止重建 .env 或删除数据卷来“修复”解密错误。回退不会自动撤销用户已发生的业务写入。
