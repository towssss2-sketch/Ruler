# 阶段 6A3C：按正文案号查找归档案件

日期：2026-10-27（北京时间）。状态：本地验证通过，最终 CI 和测试包见本轮 PR，待用户验收。分支 `feat/ingestion-case-number-match`，基于未合并 [PR #30](https://github.com/towssss2-sketch/Ruler/pull/30)。[本轮 Actions](https://github.com/towssss2-sketch/Ruler/actions?query=branch%3Afeat%2Fingestion-case-number-match)。没有自动合并或生产部署。

## 用户可见变化

正文建议带入归档表单后，打开“选择案件”，点击候选案号即可精确查找本人未删除案件。中英文括号和空白统一；同号不同法院全部分页列出，显示法院、案由和案件状态。即使只有一条结果也不自动选中；主动选择后仍需确认归档。查找本身不修改材料归属、原件、容量或案件数据。

没有分类建议但提取到案号时，预览提供“按案号选择案件”；可以先选案件，再从原有 11 类中补选类别，未补选不能归档。已归档或忽略历史保持只读预览，不开放这个归档入口。

精确未命中和请求失败分别提示，不隐式扩大到案由或姓名。用户可以主动输入关键词搜索其他案件，或清除案号条件；切换候选/搜索回第一页，分页和失败重试保留当前条件。关闭窗口或会话结束不会因迟到响应恢复旧列表。

## 实现与范围

- 复用 `GET /cases`，新增可选 `caseNo` 精确条件，沿用建案的完整格式/长度/括号/空白规范。非法、空、重复、未知字段等返回 400；省略条件保留原有搜索。精确条件与法院、状态、阶段、关键词取交集。
- 服务端绑定当前 OWNER 与 `deletedAt=null`，同一 RepeatableRead 事务计数/读取，按更新时间与身份稳定排序，保留原有分页上限。返回原案件摘要，不附加当事人详情、联系方式、内部用户或加密字段。
- 结案记录仍供人工核对；同号不同法院不合并。协作组仍未开放，不因此扩大访问范围。原 v3 的协作案件、姓名模糊匹配和自动 Match 管道继续待实现。
- 客户端按精确条件请求服务端，不用当前页筛选伪造全量匹配；核对结果案号、分组、分页、唯一身份、阶段/状态和摘要结构，坏响应不当作“没有案件”。离线先筛完整内存记录再分页，并明确是虚构体验。
- 最终归档仍走原授权和 assignmentRevision 事务；建议不能绕过待定状态、案件权限或分类确认。没有新增依赖、迁移、AI 调用、设备权限或公共服务。

## 不读代码的验收方法

1. 从本轮 PR 下载 Android 测试 APK 或完整 Windows ZIP，安装/解压后打开。默认包无需配置账号即可进入“开始虚构体验”。
2. 新建虚构案件，案号填 **`(2026)虚构民初90号`**，法院和案由填写虚构内容。也可用同一案号、不同虚构法院再建一案，观察多个匹配结果。
3. 打开“材料待定区”→“添加虚构文件示例”→“查看正文示例”→“按建议选择分类”→“选择案件”。
4. 点击“查找 (2026)虚构民初90号”，核对列表法院、案由和状态，再主动选择其中一案。不要把点击查找当作已经归档。
5. 确认分类为“服务合同”，也可改选法院文件等其他类别，然后“确认归档”。在归集历史及该案件的示例文件中核对去向；取消不应产生文件。
6. 没有同案号案件时，应显示明确未命中；可主动搜索已有案件，系统不会默默选另一个。小屏可上下滚动，多个案号按钮可横向滚动。
7. 或下载 `ruler-client-experience`，解压打开 `client-acceptance.html` 查看中文场景和截图。回复“通过”或“不通过＋现象”即可。

两张新图分别为：`client-ingestion-match.png`（协议替身 Widget 的同号不同法院列表）；`client-ingestion-match-demo.png`（实际应用离线窄屏大字深色渲染）。均已本地查看，不是真机截图。离线正文固定为虚构示例，不读取设备文件，退出应用后清除。
