## 阶段 1 可逆工程选择（不关闭以上业务决策）

- Prisma 6 原生多文件 schema，根入口与迁移路径明确配置；保持所有新文件小于 400 行，不换栈。
- 敏感字段以 ByteA 保存 AES-256-GCM 信封，逻辑富文本 JSON 序列化后加密；随机 nonce、字段/记录 AAD、域隔离 HMAC 盲索引。数据库只检查信封结构，不能代替密码学认证；生产密钥托管、轮换和完整资源授权留待专门阶段。
- 案号唯一约束限定同所有者、法院及未删除案件；审计、客户端访问日志、RT 流水追加后禁止修改及删除，即使存在 deletedAt 列也不能用于改写历史。
- 法定期限 dueDate 可为空，填写确定日期必须有确认元数据；本阶段不计算期限，也不核验确认人的律师资格。
- RT 使用 Decimal(20,6)，校验并发余额/流水快照一致性；定价默认关闭，订单仅预留 UUID，支付、退款与合规 D-07 保持待决。
- 归集记录可重新匹配；旧文件软删除后保留原来源关联，活动文件必须与归集的当前案件和渠道一致。所属案件及不可变来源锚点禁止修改，避免外键级联扩大范围。
- 已使用容量允许超过降级后配额；禁止负容量，后续上传与只读规则按原需求实现。
- 阶段 1 PR 以阶段 0 分支为基线；阶段 0 未验收、未合并，继续开发不视为验收。

## 阶段 3 保守工程选择

- 原 v3 案件级联删除与 DEADLINE_RULE 任务禁止删除存在交叉约束：本阶段拒绝删除含法定期间记录的案件，允许标记结案并保留任务，避免自行决定清除法律提醒。后续期间模块明确处理；D-05 不关闭。
- 其他用户的归集资料不随本人的案件删除而擅自归档；触发该边界时拒绝整次删除，完整协作归属规则留阶段 9，D-08 不关闭。
- 案号统一中英文括号和空白；当事人提供完整列表时按 id 同步；历史日志保留；冲突候选只查本人历史（含软删除）。详见阶段 3 案件管理约定。
- 新增的 class-validator 是原 v3 指定依赖，锁定 NestJS 10 兼容的 0.14.4；配置仍用 zod，不换栈。独立字段加密环境密钥不会覆盖已有值。

## 阶段 4A 可验证拆分与存储约定

- 按蓝图分成 4A 存储驱动/签名与 4B 文件业务闭环，未删减原第 4 节功能。4A 没有开放未授权的对象接口；4B 才实现上传票据、登记、版本、配额和完整资源权限。
- 双驱动使用原需求指定 SDK，OSS 采用官方 V4；真实云权限、桶策略、凭据刷新和联调保持未执行，不新建真实云资源。
- 签名限制十分钟并绑定上传长度、MIME、协议 MD5 校验值；不是一次性令牌，也不是抗碰撞内容认证。4B 必须防止已登记文件被尚有效的上传链接覆盖，设计临时对象到正式对象的校验/复制和失败补偿。
- 本阶段仅本机虚构文件测试；物理 delete 只是内部驱动能力，不代表已实现用户文件删除政策或配额释放政策。

## 阶段 4B 保守工程选择

- 沿用已验证的 OWNER-only，阶段 9 再开放协作矩阵；容量始终按案件 owner 核算。没有擅自扩大协作授权，D-08 保持待决。
- 软删除保留文件、配额和历史；不先决定真实资料销毁政策。删除当前版本时提升最近未删除版本，客户门户尚未开放。
- 持久票据隔离临时/正式键，版本在申请时分配、允许跳号；元数据实际核验，事务内所有者行锁防跨案件超额。业务元数据只在完成登记后可见。
- 对象副本失败留在票据中追踪，过期回收必须检查正式记录，避免数据库提交结果不确定时误删；批次限量且失败可重试。生产调度、监控、备份与容量释放策略仍待专门验证。
- 第九条迁移只新增辅助票据表，生命周期以 expiresAt/completedAt/cleanedAt 表达，不提供用户修改或删除票据的接口；签名不入库。没有新增 npm 依赖或换栈。
