## 正文预览与规则候选（6A3A，2026-10-26）

- 原 v3 第 6 节已逐项指定 `pdf-parse` 与 `mammoth`，本轮锁定 2.4.5 / 1.13.0（兼容既有 Node 20.20.2），不属于未列明的新增依赖，不另请求重复授权。没有更换技术栈；传递依赖随 lockfile 固定。
- 先提供按需预览，原件/原 rawContent 密文/归集状态/容量不改；提取正文仅返回本人、不另落库。后续持久化提取文本须沿用字段加密。审计只留 attemptId、开始/结束及固定失败原因；进程中断只留下开始记录，重试是新尝试，不宣称完整队列或自动恢复。
- 独立子进程不继承应用环境、丢弃 stdout/stderr，15 秒超时、128MiB V8 堆；输入至多 10MiB、PDF 100 页、正文 100000 UTF-16 码元。DOCX 中央目录及每项实际展开长度预检，合计至多 20MiB/256 项；拒绝加密、多卷、ZIP64。上述资源边界只限制预览，不降低既有上传上限。子进程不是 OS 安全沙箱，也不把 V8 堆限额说成总内存限额。
- 规则版本 title-v1 只识别开头独立标题；冲突、未知不默认归 OTHER，不改用户原分类。案号最多十个去重候选并标明截断；不自动匹配案件、生成法律期限、任务或调用 AI。图片 OCR、旧 DOC、视频、扫描件、密码文件等保留人工处理入口，客户端预览按钮由后续 6A3B 接入。
- 容量控制每实例同时两份、每用户一份；不把本机并发控制称为分布式队列。现有全局限流保持。解析前后均复查所有者和删除状态，处理中被删除不返回正文；结果响应禁止缓存。
- `npm audit --omit=dev` 在本轮报告 13 项（8 高、5 中），涉及依赖及其版本均在本轮之前的锁文件中；新增解析依赖树未出现在公告结果中。既有 D-06 维护/升级风险仍待决定，本轮不顺手升级基础栈，也不将测试通过说成可生产上线。D-05/D-08/D-10 不变。
