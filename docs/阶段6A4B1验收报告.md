日期：2026-11-08（北京时间）。基于已推送、尚无已确认 PR 的 6A4A 分支提交 `34cf71f`，本轮独立分支 `feat/ingestion-classification-records`。用户持续授权开发，不代表验收、合并或部署授权。

## 本轮实现

此前分类建议只随正文预览临时返回；现在每次成功提取会把分类值、固定判断原因和规则版本与成功状态、结束审计放在同一事务保存。已实现本人指定历史尝试的只读接口，重登或换连接后可读取原结果，后续规则变更不会重算历史。仍是建议，必须人工确认案件与分类才能归档。

- 第 14 条迁移向 IngestionPreviewAttempt 增加三列：classificationCategory、classificationReason、classificationRuleVersion。只使用既有11类枚举、固定原因和 title-v1，不新增正文、案号、姓名、文件名、对象键或签名存储。不改变既有加密策略或引入依赖。
- 数据库要求三列全空，或成功记录上的完整有效组合；命中标题必须有类别，无标题/冲突必须无类别，拒绝 NULL 绕过。既有终态不可变触发器同时保护新增字段，不能改写/删除结果或回填旧成功记录。
- `GET /ingestion/:id/preview-attempts/:attemptId/classification` 实时检查本人有效账号、未删除附件及尝试关联；未知/他人/错配拒绝。无查询参数，原始未知/重复/原型键拒绝，响应 private,no-store。
- RECORDED 返回 `{ruleVersion,category,reason,requiresConfirmation:true}`；旧版成功记录返回 NOT_RECORDED；处理中、提取失败或中断返回 NOT_AVAILABLE。后两者 classification 为 null，不将旧记录缺失误报为“未识别标题”。
- GET 不重新提取、写审计、调用 AI 或改变归档状态；按尝试 ID 读取，后续重试不覆盖旧分类。提取历史旧接口与 POST 预览响应保持兼容。
