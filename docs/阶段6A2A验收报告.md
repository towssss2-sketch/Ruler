## 本轮行为和体验范围

原先文件上传必须先选案件。现在后端可以在尚未确定案件时接收一份文件，进入当前用户的待定区，保留可下载原件；后续再补客户端的选择文件、11 类分类和指派案件。**本轮没有新增客户端文件待定区入口**，现有客户端只能显示接收记录的文件名说明，不能通过该页面选择或下载暂存文件。

| 后端行为 | 实际效果 |
|---|---|
| 无案件申请、私有直传和完成接收 | 先拿上传票据，上传后验证实际大小、MIME 和 MD5；接收前不创建待定记录 |
| 服务端真实内容去重 | 冻结私有副本，读取字节计算 SHA-256，再做按用户/渠道/文件域隔离的 HMAC；同内容改名保留首份名称，同名不同内容分开 |
| 同票据重试、并发、忽略后重传 | 同内容只保存一次、只占一次原件容量，重复已忽略文件保持忽略状态 |
| 与案件文件共用容量 | 共同核算已用空间和未完成上传预约；最多二十张有效未完成票据，两个入口并发不能越过配额 |
| 本人授权下载 | 实时校验账号与归属，只返回短效下载；别人、已删除记录或缺失对象被拒绝 |
| 失败重试和过期清理 | 复制、读取或审计失败整体回滚登记/容量；票据保留供重试。每分钟最多清理十张到期超过一分钟的残留，已接收/忽略/软删原件保留 |

沿用 PDF、DOC、DOCX、JPEG、PNG、MP4 六种格式，单文件最大 200MiB，签名最长十分钟。大小/MIME/摘要校验不等于正文解析、病毒扫描或真实性鉴定。流式指纹读取限定精确长度及三十秒流读取时间，不一次性把整个文件装进内存。

正式案件文件的 11 类分类（含起诉材料、答辩材料、法院文件、传票、服务合同）继续保留。此轮不将文件暂存自动转为 Document，不产生分类、案件匹配、AI 结果、任务或法定期间。WECHAT 仅标记手动接收微信文件，不读取聊天或调用微信接口。

## 不需要代码的验收方法

1. 打开本轮 PR 中的 Actions 链接，在产物区下载 `ruler-ingestion-file-validation`。
2. 解压后双击 `ingestion-file-acceptance.html`，查看“本轮实际行为”和逐项结果，应为 19 项通过、失败和未运行均为 0。
3. 核对范围说明：本轮是后端暂存，客户端选文件、分类和指派仍待下一块；报告不会要求你找尚不存在的按钮。
4. 有空回复“通过”或“不通过＋现象”。你无需读代码、改配置或运行终端。当前安装包的原有案件分类上传仍保留，默认包没有公共测试服务或账号。

## 数据、限制与回退

追加 IngestionUpload/IngestionFile 表和同用户组合外键、不可变身份/完成/清理约束；不改历史迁移。对象采用独立用户归集命名空间，不伪造案件 ID。原文保存加密的文件名说明，不是提取正文；附件名称和对象键沿用既有文件模块的存储边界，审计只记录内部标识、不记录名称/内容/签名。

忽略或软删除不删除原件、不释放容量，没有用户容量回收入口。已签发下载链接最长十分钟内仍可能有效，不能承诺即时撤回。重复文件副本到期后清理，临时物理空间会暂时超过逻辑已用量。相同内容即使重新命名也返回首份名称；当前不支持撤销忽略。

测试只使用虚构文件和本轮随机独立 schema/Redis 前缀/MinIO 桶，未重置现有数据或替换字段密钥。回退保留新表、票据、附件、配额和对象；旧后端不认识暂存预约，不能直接回退后继续开放上传，应停写或前向修复。不得删除原件或将已用空间清零作为回退办法。
