# 阶段 11A2B3B2：本机 HTTPS 与真实客户端双入口联调

日期：2026-10-18。基于未合并 PR #13。本轮补齐实际后端的本机 TLS 启动能力，并验证客户端通过不同 HTTPS 入口访问 API 和文件。公共服务和账号仍未交付，D-10 未关闭。

## 已交付与边界

- 后端支持可选证书/私钥文件。两个配置都不设置时兼容原 HTTP；显式启用后要求开发/测试环境和本机 HOST，材料完整、未过期、已生效、匹配主机及私钥，最低 TLS 1.2；无效立即拒绝启动，不降级。
- 文件入口使用上轮独立签名地址，测试专用 HTTPS 转发器把请求送至本机 MinIO，保留签名 Host/路径/查询；真实客户端上传、下载、版本、重登和账号隔离通过。
- 临时自签证书在随机私有目录生成。默认客户端先拒绝 API 和文件两个入口的证书；随后测试工具仅在局部区显式信任本次证书，保持标准握手和主机校验。无忽略证书回调、无全局关闭 TLS、无系统信任库安装；工具及私钥不进入安装包。
- 测试入口实际收到文件 PUT/GET，未收到登录 Authorization 或 Cookie。测试结束清理本次服务器、证书、数据库 schema、Redis 前缀及桶，不触碰既有开发数据或字段密钥。
- 不新增依赖、不迁移数据库、不购买资源、不公开端口、不部署生产；开发注册/验证码/文档入口隔离及用户账号交付尚未实现。

## 用户如何验收

在本 PR 成功的 Actions 下载 `ruler-client-https-validation`，解压后打开 `client-https-acceptance.html`。应看到 10 项通过、0 失败、0 跳过，以及默认客户端拒绝两个入口未受信任证书的说明。原 HTTP 的 9 场景报告仍由 `ruler-client-api-validation` 提供。

无需配置证书、运行命令或重装客户端。可以回复“通过”或“不通过＋报告现象”。本机 HTTPS 通过不代表手机已能连接；可达服务、域名和安全交付的账号准备好后再做真机点击验收。

## 风险与回退

临时自签证书仅供测试；公共可信证书、证书续期和运行保障未实施。实际后端在启动时加载材料，更新需重启，没有热更新或自动续期。测试转发器不能作为生产网关。D-05、D-06 和 D-10 仍待决。

撤回本 PR 恢复原 HTTP 工厂和联调，无数据库回滚或对象清理要求，不修改现有加密密钥。所有 PR 仍待用户验收，不自动合并。
