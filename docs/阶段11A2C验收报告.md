# 阶段 11A2C：文件分类归档与客户端体验

日期：2026-10-18（北京时间）。基于未合并 PR #15，按用户最新反馈优先推进文件分类，账号交付方案顺延。原始需求未被删减，所有 PR 仍待用户验收。

## 原提示词明确要求了什么

- `RULER-原始需求-v3.md` 第 1 节 Document 模型列出九类：起诉材料、答辩材料、证据材料、开庭传票、授权材料、庭审笔录、代理意见、判决书、其他。
- 第 4 节规定上传登记 `category` 必填，文件列表支持按 `category` 查询。
- 第 11 节规定文件页按分类分组，并支持上传、下载和版本。
- 用户本轮补充“法院文件、服务合同”：作为独立类别加入，原九类保留。法院文件用于其他法院通知、裁定等；已有传票和判决书仍单列。手动分类不触发法律期限计算；AI 识别仍属未实现的第 6 阶段。

## 本轮实际变化

后端原先已有分类字段、必填校验和筛选；客户端已有上传下拉框，但默认“其他”，列表仍平铺。本轮新增两类，后端与客户端共十一类，数据库追加枚举迁移并重新生成客户端。

连接版上传未选类别时按钮不可用；选定后原样交给接口保存。从分类筛选进入上传时预选该类，新版本预选原分类；传输开始及原票据重试期间分类不可改。文件列表按类别分组，每组标明“本页”数量，保留完整分页、历史版本和资源权限，不把本页数量称作整案统计。

离线体验也可以选择十一类并添加示例条目，按类分组；各类别示例版本独立递增，删除后不复用编号。这仍只是条目演示，不读取设备文件、不上传真实材料。连接版的真实文件选择与上传已有实现，但用户可达服务与登录账号尚未交付。

## 你如何体验

1. 下载本轮成功 Actions 的 `ruler-android-debug-apk` 或 `ruler-windows-test-zip`，按 README 所列方式安装/解压；无需改配置。
2. 打开“开始虚构体验”，新建虚构案件，进入“示例文件”。
3. 在“示例材料分类”选择“起诉材料”，点击“添加示例文件版本”；再分别选择“法院文件”“服务合同”添加。应出现相应分组。
4. 同一类再添加一次，看到该类版本 2；其他类别仍是版本 1。操作仅演示分类，关闭应用后清除。
5. 也可下载 `ruler-client-experience`，打开 `client-acceptance.html` 直接看中文报告与实际渲染截图。真实分类上传的独立证据在 `ruler-client-api-validation`、`ruler-client-https-validation`、`ruler-client-restricted-validation`。

回复“通过”或“不通过＋操作现象”即可。当前不要在“测试服务登录”输入真实账号或期待连接公网。

## 风险与回退

新增第十条迁移只追加 COURT_DOCUMENT / SERVICE_CONTRACT，保留旧九类、数据和索引，不重新解释或批量改写历史文件。旧安装包不认识新类别；未来部署需先迁移并更新后端，配套发布新客户端。

PostgreSQL 枚举值不能简单删除。若已有新类别数据，禁止直接降级旧后端/客户端、删除记录或静默映射为“其他”；先关闭受影响入口，准备兼容版本或经审阅的数据处理方案。当前没有生产部署，无需生产回滚。

本轮没有自动分类、批量重分类、拖拽上传、可达服务、账号交付、离线持久化或真机验证；D-05、D-06、D-10 仍待决。不自动合并、不购买或部署。
