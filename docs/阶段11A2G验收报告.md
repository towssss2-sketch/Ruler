## 实际交付

原始 v3 第 3 节要求关键词搜索、法院/阶段/状态筛选和更新时间排序。本轮接入已有 GET /cases 查询参数，无后端规则、依赖、迁移或权限变更。

- 在线与离线案件列表增加“筛选与排序”：法院全称、全部/一审/二审/执行/再审、全部/进行中/已结案，以及最近更新优先/较早更新优先。
- 法院去除首尾空白后精确匹配，留空表示全部；多个条件取交集，并与关键词一起生效。关键词查案号、案由和当前当事人姓名，法院使用专门筛选条件。
- 条件先在弹窗内编辑，“应用筛选”才改变列表；取消不查询。“重置条件”只改草稿，应用后生效；列表上的“清除筛选”立即恢复默认条件和排序，保留独立关键词。
- 在线由后端执行全量筛选后分页，每页 20 条；切换筛选或关键词回第一页，翻页和重试保留已应用条件。列表总数来自服务端，不把当前页局部过滤当成整案查询。
- 条件摘要始终可见；加载、失败和无匹配分别展示。慢的旧响应不会覆盖新结果；会话失效仍销毁旧账号导航与列表。
- 离线对本次内存记录筛选、按案件更新时间排序，同时间按身份稳定排序。创建、修改基础信息和名单更新案件时间；任务和示例文件操作保留案件时间。离线不声称服务端查询或磁盘持久化。

协作组仍未开放，本轮仍为当前账号主办案件；没有引入跨用户搜索。完整其他案件字段编辑留后续。

## 所有者点击验收

1. 下载本轮成功 Actions 的 Android APK 或 Windows 测试 ZIP。Android 解压安装 APK；Windows 解压并保留配套文件后运行 EXE。
2. 打开“开始虚构体验”，创建两个虚构案件：第二个案件改一个案号和法院，例如“虚构测试法院乙”，避免重复。
3. 在第二案的“编辑案件信息”中选择“二审”和“已结案”，保存后返回案件列表。
4. 点“筛选与排序”，法院填“虚构测试法院乙”，阶段选“二审”、状态选“已结案”，点“应用筛选”，应只显示第二案。
5. 重新打开筛选，把法院改成“虚构不存在法院”后点“取消”，原列表不应变化；再应用该法院时应出现无匹配提示。点“清除筛选”恢复全部。
6. 切换“较早更新优先”，再打开较早案件修改案由并保存，返回列表观察排序变化。输入虚构当事人姓名可继续与筛选组合查找。
7. 不安装也可下载 `ruler-client-experience`，打开 `client-acceptance.html` 查看中文结果和界面截图。API/HTTPS 报告是独立真实联调证据。

只需回复“通过”或“不通过＋现象”，无需读代码、改配置或运行命令。

## 风险与回退

- 默认安装包仍没有公共测试地址和账号；可离线点击筛选，不能在设备上直接体验真实数据库查询。D-10 未授权购买/部署，不公开本机服务。
- 在线仅查询当前账号主办案件，沿用后端权限；协作组和律所范围仍待第 9 阶段/D-08。D-05 法律期间、D-06 版本维护等原待决事项不变。
- 返回列表仍按当前条件显示；编辑后不再符合条件的案件会离开当前结果，但不会因此被删除。并发修改或新建会改变分页位置，刷新后以服务端结果为准。
- 筛选只在当前页面内存保存；退出应用/结束会话不保留。法院全称不匹配时可清除条件重新查找，不自动改写法院名称。
- 无迁移与新增依赖，可回退客户端和测试代码；服务端案件不变，回退不删除数据库或文件。没有自动合并或生产部署。
