## 用户可见变化与边界

原始 v3 第 1 节 Task 包含 title、description、dueDate，第 5 节要求更新任务。本轮接入已有手动任务 PATCH，无后端规则、依赖、迁移或权限变化。

- 案件内任务卡新增“编辑任务”，预填标题、描述和工作日期。在线新建同样可填写三项；离线保留快捷添加标题，再打开编辑补齐资料。
- 标题必填，最多 255 字；描述可空，最多 10000 字，首尾空白去除而内部换行保留。卡片展示前三行描述，完整内容可在编辑表单中查看。
- 日期为 YYYY-MM-DD，按后端已有 1000–9999 年边界验证真实日历日期与闰年。无效日期、时间/时区后缀不接受；超过输入长度也不会静默截短成合法日期。
- 空白描述/日期保存为 null，明确清空；仅 PATCH 三字段，不发送状态、source、可见性或确认资料。已完成任务编辑后仍完成，完成/恢复不会丢失描述和日期。
- 保存中禁用输入、按钮和系统返回；失败保留草稿可重试，取消不写。成功后单独重读列表，读取失败只重试 GET，不重复 PATCH。会话失效销毁旧任务页面和输入。
- 在线仍请求 MANUAL 来源，响应非手动来源、非法日期、状态或描述则整次拒绝，不把期间任务交给普通编辑器；最终权限仍由后端裁决。
- 编辑后保留当前页并重读；改日期可能按服务端排序移到另一页。离线任务仍按本次添加顺序显示，不冒充数据库排序；资料只在内存，任务编辑不更新案件排序时间。

工作日期只作普通任务安排，不计算法定期间、不发送提醒。今日汇总界面、法定期间登记/确认仍未实现，D-05 保持待决。

## 只需点击的验收步骤

1. 下载本轮 Android APK 或 Windows ZIP，解压安装/运行。Windows 保留同目录配套文件。
2. 点击“开始虚构体验”，创建虚构案件，切换“工作任务”，点“添加体验任务”。
3. 点任务卡的“编辑任务”，修改标题，描述填两行虚构文字，日期填 `2028-02-29`，点“保存体验修改”。卡片应显示新资料。
4. 点“标记完成”，再点“编辑任务”修改描述并保存，任务仍为已完成；点“恢复待办”，日期和描述仍保留。
5. 编辑日期为 `2026-02-29` 应提示无效，输入保留；清空描述和日期再保存，应显示“描述：未填写”和“未设工作日期”。
6. 修改后点“取消”，原保存值不变。切换到“案件信息”再回“工作任务”，本次数据仍保留。
7. 不安装可下载 `ruler-client-experience`，解压打开 `client-acceptance.html` 查看中文结果和实际渲染截图。

无需读代码、运行命令或改配置。可回复“通过”或“不通过＋现象”。没有公共测试账号，设备无需尝试连接本机测试端口。

- 仅限虚构资料；在线沿用描述 AES-256-GCM 加密、OWNER 授权和审计，客户端不增加磁盘缓存或 AI 外传。
- 三字段整体保存沿用最后成功更新生效；同时编辑同一任务可能覆盖资料，没有版本冲突合并。未知写结果应先刷新核对；已知保存成功后的读取失败仅重读。
