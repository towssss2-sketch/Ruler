# 阶段 0 依赖与环境决策

## 范围

只建立基础工程、欢迎页、开发服务、真实检查和测试包流水线。
不提前实现原始需求阶段 1–12 的业务功能，不创建假登录或假案件接口。
EnvironmentProbe 仅是迁移和读写探针，集成检查用后即删除记录。

## 必要依赖依据

| 依赖 | 用途与依据 |
|---|---|
| NestJS common/core/platform-express/testing 10 | 原始指定后端及其默认 HTTP 适配器、测试工具 |
| TypeScript 5、Node 20 类型 | strict 编译和类型检查 |
| Prisma/client 6 | 指定 ORM，保留 Node 20 兼容性，生成客户端和部署迁移 |
| reflect-metadata、rxjs | NestJS 的运行依赖和响应拦截器 |
| zod、Pino | 原需求指定的配置校验与结构化日志；日志不记录输入和底层异常 |
| Jest、ts-jest、Jest/Express 类型 | 指定单测框架及 TypeScript 编译适配；不增加 supertest，HTTP 测试用 Node fetch |
| ESLint、typescript-eslint | 阶段 0 lint/禁止 any/明确返回类型；保持兼容工具版本 |
| AWS SDK v3 client-s3（开发依赖） | 原需求指定 S3 协议；本阶段只验证 MinIO 认证上传下载，不实现业务存储驱动 |
| Flutter SDK、flutter_test、flutter_lints | 原需求指定客户端及分析/Widget 测试 |
| 官方 Visual C++ x64 CRT | Windows Flutter 程序所需运行库；从 runner 的官方 Visual Studio Redist 目录随测试包交付，验证必需文件存在 |
| Riverpod、go_router、drift | 指定状态管理、路由、缓存栈；前两者实际用于欢迎页，缓存业务留待后续 |

版本在 manifests 中固定，npm/package-lock 与 Flutter/pubspec.lock 提交；
CI 使用 npm ci 和 flutter pub get --enforce-lockfile。
没有引入业务范围外的服务供应商或付费依赖。

## 平台与信任

- Node 安装使用官方归档并校验 SHA-256。
- Flutter 3.38.7 从官方 Git 标签检出，Android/Windows 工程由该 SDK 的官方模板生成。
- Android command-line tools 19.0 的归档用 Google 官方仓库 XML 给出的校验值验证。
- 本机原有 Java 仅运行时，缺少 javac；已安装经官方 SHA-256 校验的 Eclipse Temurin JDK 17。
  AGP 8.11.1 默认要求 Build Tools 35.0.0，即使 SDK Platform 为 36，也须安装对应 Build Tools。
- JDK 17 使用平台系统 Java 信任库，修复代理证书链识别，未关闭 TLS 或校验。
  本机 Kotlin 使用 Gradle 可写缓存中的 in-process 配置，避免受限主目录下的编译 daemon 问题。
  CMake 3.22.1 由 Android 官方工具安装并用于实际 APK 构建。
- Gradle 8.14 wrapper 固定官方 SHA-256；Prisma 引擎保留官方校验。
- MinIO 官方镜像仓库在本机返回拒绝访问；改用官方 GitHub release 的 Linux amd64 deb。
  脚本和 Dockerfile 均校验固定 SHA-256 后再提取执行文件。
  当前版本及镜像是开发基座，不是生产存储交付，也未宣称完整安全审计通过。
- Compose 端口只绑定本机，开发密码随机生成且不入版本控制。
- Windows 构建由 windows-2022 runner 执行；设备安装与体验仍需用户验收。

## 保守解释

1. Dart 源文件按官方 lower_case_with_underscores 和 *_test.dart 命名，保证 SDK 分析和测试发现；
   TypeScript 保持 kebab-case。原通用文件名规程对 Dart 作语言约定解释，未禁用 lint。
2. 阶段 0 的 /health 是存活检查，/health/ready 是真实数据库就绪检查；
   Redis/MinIO 使用独立功能检查，不伪称业务全部就绪。
3. 正式 Android 签名留人工闸门；删除模板中 release 使用 debug 签名的配置，CI 只构建 debug APK。
4. 架构固定 Node 20/NestJS 10 不变。D-06 升级决定保留待确认；
   同主版本兼容修订和 multer 安全覆盖用于减少已知依赖问题，后续业务不得直接视作安全上线依据。
5. npm audit 最终报告 44 个受影响依赖条目，已消除 critical；Jest/Prisma 工具链等传递问题仍在，
   以及 NestJS 10 固定架构下的 moderate 问题。该诊断为 FAIL，详见验收报告，不隐瞒或关闭审计。
