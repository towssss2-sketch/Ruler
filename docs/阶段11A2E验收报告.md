日期：2026-10-19（北京时间）。基于未合并 PR #17，本轮状态为开发完成、待验收；最终 CI 和安装包以[本轮分支的 Actions](https://github.com/towssss2-sketch/Ruler/actions?query=branch%3Afeat%2Fclient-case-parties)为准，不沿用前轮 CI 作为本轮结果。

## 实际交付与原始需求

原 v3 第 3 节要求带当事人及文件/待办统计的案件详情，第 11 节要求当事人动态增删。本轮接入已有授权 GET/PATCH 接口，无新增后端业务、数据库迁移或第三方依赖。

- 连接版案件内增加“案件详情与当事人”：展示基础信息、当前文件数、待办数、审判员、书记员及电话、费用状态、备注、当事人。后四类额外案件信息本轮只读。
- “编辑当事人”支持原告、被告、第三人，修改姓名、电话、证件号、地址，新增或确认移除；姓名必填，可选资料清空明确提交 null。至少保留 1 人，最多 100 人，对屏幕外的输入也进行校验。
- 修改已有当事人时保留 id，新记录不带 id，由后端分配。只 PATCH parties，不提交案号、费用、文件、任务等其他字段。移除只修改草稿，最终保存才在服务端生效；取消整个编辑不写入。
- 写入成功退出编辑后，独立重新读取详情；重读失败显示重试入口，只重试 GET，不重复 PATCH。写失败保留输入；保存期间禁用重复提交、取消与系统返回；会话失效销毁在线详情和表单。
- 离线虚构体验提供同一详情和编辑界面，数据只保存于当前内存。离线统计明确叫“示例版本”，不冒充实际上传文件。

新建案件表单本轮仍先录入一个原告，再进入详情维护完整名单；新建时一次填入多人、利益冲突检查界面、完整案件字段编辑、协作角色 UI 仍待后续，不能称为完整案件管理交付。

## 所有者点击验收

1. 下载本轮成功 Actions 的 Android APK 或 Windows 测试 ZIP；Android 解压后安装 APK，Windows 解压两层后保留全部文件并运行 EXE。
2. 打开“开始虚构体验”→“新建案件”→使用默认虚构信息创建。
3. 在“案件信息”打开“案件详情与当事人”→“编辑当事人”，填写“虚构原告甲”。
4. 点“添加当事人”，下滑到新增行，选择“被告”并填“虚构被告乙”；可选资料只填虚构占位文字，点击“保存体验当事人”。
5. 再次编辑，修改姓名、角色或清空可选资料；有两人时可点“移除此人”并确认，保存后详情只显示保留者。只有一人时移除按钮不可用。
6. 改一次姓名后点“取消编辑”，确认原姓名未改变；返回再进入详情，本次内存名单仍在。关闭应用后清除属于离线体验边界。
7. 不安装也可下载 `ruler-client-experience`，打开 `client-acceptance.html` 查看中文结果和 `client-parties-editor.png`、`client-parties-detail.png`、`client-parties-demo.png`。真实保存与权限证据见独立 API/HTTPS 报告。

回复“通过”或“不通过＋操作现象”即可，无需读代码、改配置或运行终端。

## 风险、边界与回退

- 安装包默认仍没有可达测试地址或账号；服务器、域名和受控账号交付待处理。D-10 未授权购买或部署；本轮不公开开发端口、不自动合并。
- 沿用现有服务端全量名单同步语义：名单中省略的原当事人会软删除，并吊销其预留门户访问记录（客户门户尚未开放）。取消编辑不触发该行为；多人同时编辑仍是后一次成功更新生效，尚无冲突合并。
- 服务响应丢失可能出现“服务端已写入、客户端未确认”；写请求不自动重放，建议退出编辑刷新核对名单后再改，避免以旧名单覆盖已保存结果。已确认写成功后的重读失败只重复 GET，专项测试已验证。
- 沿用已有 AES-256-GCM 加密、资源权限与审计；数据只在当前界面内存，未新增磁盘缓存/个人信息外传方案。截图和联调只用明确虚构资料。
- 本轮无迁移，可回退客户端代码；已保存当事人仍留在服务端，回退旧包只失去此界面，不删除数据库或对象。前序分类枚举迁移仍按其报告的兼容要求保留。
- 后续继续新建时多人录入、案件筛选及利益冲突检查界面；D-05、D-06 等原有待决事项保持原状态。
