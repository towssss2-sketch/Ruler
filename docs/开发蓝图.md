# RULER 分阶段实施蓝图

本文件只为原 v3 的 12 阶段增加**机器执行节奏与验收闸门**，不替代业务规格。每阶段拆为小 PR，且完成一个阶段需有可重复的测试证据。

| 阶段 | 内容（沿用 v3） | 示例阶段验收结果 |
|---|---|---|
| 0 | 工程与 CI/环境基座（新增前置） | 后端 lint/typecheck/test 可运行；Flutter smoke test；容器启动；CI 显示真实测试 |
| 1 | Prisma Schema v2 | migration 可从空库执行且能回滚策略说明；索引与敏感字段核对 |
| 2 | 后端骨架+鉴权 | 注册登录/刷新/登出/越权 403 e2e |
| 3 | 案件管理 | CRUD、利益冲突、审计、重复案号/权限测试 |
| 4 | 文件存储 | MinIO/OSS 抽象、配额、短效下载签名、越权测试 |
| 5 | 任务/法定期间 | 截止规则边界测试、提醒幂等、人工复核机制 |
| 6 | SMS/Email/微信归集 | 虚构材料的归集全链路；第三方平台接口单独验证，验证码不得绕过 |
| 7 | AI 案件分析 | 模拟 LlmClient，结构化失败、安全提示、可编辑时间轴 |
| 8 | AI 文书生成 | 初稿编辑/定稿/引用核验标记、无杜撰测试 |
| 9 | 协作权限 | OWNER/EDITOR/VIEWER 权限矩阵、移除立即失效 |
| 10 | 会员计费/RT | 支付**沙箱**幂等、余额并发、退款/到期；正式支付人工批准 |
| 11 | Flutter Windows/Android | 真实可安装包、关键任务 UI 测试、短信权限体验与人工验证 |
| 12 | 交接文档 | HANDOVER.md、部署手册、测试与风险清单、源码/依赖清单 |

## 执行策略
- 2026-10-16 用户要求边推进边准备客户端体验：提前拆出 11A1 离线虚构交互版，以及后续 11A2 真实 API/文件闭环；不把演示视为完整第 11 阶段完成。阶段 5B 的法律决策仍独立处理，未批准前只作设计准备。
- 11A2 再拆为 A（真实登录/会话/案件/常规任务，真实 Dart 到数据库联调）和 B（设备文件接入、可达测试服务及账号交付）。代码和联调通过不等于用户手机已能连接；不得要求所有者改配置或自行架服务。
- 11A2B 拆为 B1（真实文件传输核心、文件列表与版本操作）和 B2（设备选择/保存、受控测试服务及账号交付）。B1 可用真实 MinIO 独立验证；B2 的新依赖遵守 D-09 确认闸门，不能把核心测试写成设备已可上传。
- 先做贯穿式最小闭环：**虚构账号登录 → 新建案件 → 上传测试文件 → 关联任务 → 运行 UI 查看 → APK/Windows 构建**；再拓展各阶段，不以界面演示代替完整安全实现。
- 每一阶段拆小 PR，如 `phase-03/case-create`、`phase-03/case-list`；每个 PR 提供可观察行为。后端复杂业务可先提供 Swagger/demo 测试录像或脚本，再在 Flutter 客户端提供体验。
- 任何事项若依赖法院线上平台、设备 SMS 权限、真实邮件 OAuth、OSS、支付或大陆备案：先用可核验 mock/沙箱完成功能，真实接入另经用户许可，**不得宣称已真实打通**。
- 每个 PR 状态为：`NOT_STARTED → IMPLEMENTING → VERIFYING → READY_FOR_USER → ACCEPTED`；异常为 `BLOCKED`/`REJECTED`。仅用户接受后标记 `ACCEPTED`。
