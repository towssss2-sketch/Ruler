# 阶段 2 鉴权设计与已确认决策

2026-10-14，用户明确同意 D-01 推荐方案：数据库是刷新会话的唯一真值来源；Redis 保存验证码和限流计数，不双写刷新会话。

- 采用邮箱验证码注册，避免真实手机号码、短信权限、收费及实际短信供应商接入。本期只有 example.invalid 内存投递适配器，无真实邮件、无公开取码接口；生产模式禁止启动。
- 密码使用 Node 内置 scrypt（N=32768、r=8、p=1、16 字节随机盐、64 字节派生结果），输入限定 12–128 字符。不存在账号执行相同成本处理，错误登录统一 401。
- Access JWT 固定 HS256、发行者/受众/类型，2 小时有效；不携带角色、案情或联系方式，每次请求查数据库会话与用户状态。随机 Refresh 凭据 256 位，只保存 SHA-256 摘要；三十天绝对会话期限，刷新不延长。
- 刷新对会话行加锁，旧凭据只消费一次；检测到已消费凭据重放，事务提交整条会话吊销后才返回 401。并发重复刷新会触发同样的保守保护，客户端必须串行刷新；自动重试不能复用已消费的旧凭据。登出立即拒绝当前 Access/Refresh，独立设备会话不受影响。
- 验证码十分钟失效，六位安全随机数，以 HMAC 保存；原子消费、错误五次销毁。验证码每邮箱每分钟 3 次、登录/注册 5 次，全部公开鉴权请求同来源每分钟 30 次；普通受保护 API 在 JWT/数据库身份校验前按来源每分钟 120 次；不信任转发 IP 头。Redis 故障关闭入口，不内存降级放行。
- resource guard 对路径中的案件/文档/任务实时反查归属；不存在/无权限统一 403。本期 OWNER 可访问，EDITOR/VIEWER 保守拒绝，CasePolicy 留扩展接口，完整协作矩阵阶段 9 实现。
- 注册、登录、刷新、重放、登出写脱敏审计；请求日志仅状态与服务端 traceId，不记录 URL、正文、邮箱、密码、验证码、令牌或数据库错误。
- 新增兼容 NestJS 10 的 @nestjs/jwt 10.2.0、@nestjs/swagger 8.1.1 与 ioredis 5.11.0，锁定版本。Swagger 固定传递依赖覆盖到 lodash 4.18.1 / js-yaml 4.3.2；没有换技术栈。最新审计 45 项（33 高、11 中、1 低、0 严重）；D-06 维护与升级决策仍未关闭。
- auth/user/case 包含真实代码；其他原需求模块目录只记录后续边界，没有空成功端点，也不声称业务已实现。
