## 用户如何体验

1. 从本轮 CI 产物下载 Android debug APK 或 Windows 测试 ZIP；Windows 解压完整文件夹后启动其中程序。构建链接及最终状态见 PR，不使用旧提交的安装包冒充本轮。
2. 进入“开始虚构体验”，新建一个虚构案件，返回案件列表。
3. 点击右上角“材料待定区”→“添加虚构文件示例”→“分类归档”。
4. 点击“选择案件”，搜索并选择刚建的案件；分类选择“服务合同”或其他类别，点击“确认归档”。
5. 检查归集历史显示“已指派”，待定列表不再显示该材料。返回案件列表打开该案→“示例文件”，应在所选分类下看到“虚构服务合同示例.pdf”。再次添加相同示例不会多出一份。
6. 回复“通过”或“不通过＋现象”。无需读代码、修改配置或运行命令。

离线示例一次会话只生成一份固定附件，可在归档前查看全部分类。真实设备文件上传/持久化/下载仍需公开测试服务和安全账号交付；目前没有服务器和域名，D-10 待决。安装包不能直接登录远程服务。

## 事务、容量与恢复边界

- `POST /ingestion/:id/assign` 只接收 caseId/category。专用守卫复用统一 CaseAccessService；两次事务均按案件→用户→归集记录→票据顺序加锁，重新检查当前资源归属及删除状态，只开放 OWNER。
- 复制前持久化 DocumentUpload 准备票据，沿用总计二十张有效票据和容量预约。内部生成的独立 pendingKey 不指向原件，也不签发上传权限；正式键遵循 owner/case/document/version_name 契约。公共登记接口不能在待定状态使用该准备票据绕过归档。
- 归档重新核验已冻结原件大小/MIME/MD5，以 ETag 条件复制，再核验目标。ASSIGNED/matchedCaseId、正式 Document、已用容量和审计在同一事务提交。来源仍为手动微信文件通道 WECHAT，并保留 ingestionId。没有伪造 AI 识别或执行任务建议。
- 复制/审计失败回滚业务记录，原件和准备票据保留；重试复用有效票据。失败或竞争丢弃的副本由既有定时回收器处理；回收先核对正式文档，即使提交结果未知、文档已软删，也不删除已登记对象。
- 归档原件与案件副本各占一份容量；这是保留历史策略的显式延续，不是移动后释放空间。清理前的失败物理副本可能临时占用存储，已用业务容量只在成功提交后增加。软删除继续保留容量。
- 未提供重新分类、改派或撤销归档；已签发链接最长十分钟内仍可能有效。纯文字转换、正文提取、自动分类、自动匹配、分享接收和任务建议另行推进。D-05 法律期间决策、D-06 依赖维护、D-08 协作、D-10 公网服务状态不变。
